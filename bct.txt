## PRACTICAL 3: WRITE A SMART CONTRACT ON A TEST NETWORK FOR BANK ACCOUNT OPERATIONS

### AIM:
To write and deploy a smart contract for a bank account to perform the following operations:
1. Deposit Money
2. Withdraw Money
3. Show Balance

### SOFTWARE REQUIRED:
1. Google Chrome
2. Remix IDE
3. MetaMask (if using a test network)

### CONCEPT:

Blockchain is a distributed digital ledger that stores transactions.

Smart Contract is a program stored on a blockchain that executes instructions automatically.

Solidity is a programming language used to write Ethereum smart contracts.

Remix IDE is an online development environment used to write, compile and deploy Solidity smart contracts.

Deposit means adding Ether to the bank account.

Withdraw means removing Ether from the bank account.

Balance means the total amount of Ether stored in the smart contract.

### STEP 1: OPEN REMIX IDE

1. Open Google Chrome.
2. Visit https://remix.ethereum.org/
3. Remix IDE will open.
4. In the File Explorer, open the contracts folder.
5. Click the New File icon.
6. Create a file named BankAccount.sol.

WHY?
Remix IDE is used to write, compile and deploy Solidity smart contracts.
The .sol extension represents a Solidity source-code file.

### STEP 2: WRITE THE SOLIDITY CODE

Copy and paste this complete code into BankAccount.sol.

```solidity
// SPDX-License-Identifier: MIT
// Specifies the open-source license of this smart contract.

pragma solidity ^0.8.0;
// Specifies the Solidity compiler version.

contract BankAccount {
    // Creates a smart contract named BankAccount.

    uint public balance;
    // Stores the bank account balance in Wei.
    // Public allows Remix to automatically provide a balance-reading function.

    function deposit() public payable {
        // Allows users to deposit Ether into the smart contract.
        // Payable allows this function to receive Ether.

        balance += msg.value;
        // Adds the deposited Ether amount to the account balance.
        // msg.value represents the amount of Ether sent with the transaction.
    }

    function withdraw(uint amount) public {
        // Allows the user to withdraw the specified amount in Wei.

        require(amount <= balance, "Insufficient balance");
        // Checks whether sufficient balance is available.
        // Stops the withdrawal if the requested amount is too high.

        balance -= amount;
        // Subtracts the withdrawal amount from the stored balance.

        (bool success, ) = payable(msg.sender).call{value: amount}("");
        // Sends the requested Ether to the account that called this function.
        // msg.sender represents the caller's wallet address.

        require(success, "Transfer failed");
        // Checks whether the Ether transfer was successful.
    }

    function showBalance() public view returns (uint) {
        // Reads the current balance without changing blockchain data.

        return balance;
        // Returns the stored bank account balance in Wei.
    }
}
```

### STEP 3: COMPILE THE SMART CONTRACT

1. Click the Solidity Compiler icon on the left side.
2. Select compiler version 0.8.x.
3. Make sure the compiler version matches the pragma statement.
4. Click Compile BankAccount.sol.
5. A green tick indicates successful compilation.

WHY DO WE COMPILE?

Compilation converts Solidity source code into bytecode that the blockchain can execute.

If an error appears, check the code and compiler version.

### STEP 4: DEPLOY THE SMART CONTRACT

1. Click the Deploy & Run Transactions icon.
2. Select Remix VM (Cancun) under Environment.
3. Select BankAccount from the contract dropdown.
4. Click Deploy.
5. The deployed contract appears under Deployed Contracts.

WHY DO WE DEPLOY?

Deployment places the compiled smart contract on the selected blockchain environment so that we can execute its functions.

Note: Remix VM is a simulated blockchain environment for practice. For an actual test-network deployment, connect MetaMask and select the required test network.

### STEP 5: DEPOSIT MONEY

1. Under Deployed Contracts, find the VALUE field.
2. Enter 2.
3. Select Ether from the unit dropdown.
4. Click the deposit button.
5. Wait for the transaction to complete.

WHY?

The deposit function is payable, so it accepts Ether and adds the deposited amount to the balance.

EXPECTED RESULT:
The deposited amount is added to the smart contract balance.

### STEP 6: SHOW BALANCE

1. Click showBalance.
2. Observe the displayed balance.

EXPECTED RESULT:
If 2 Ether was deposited, the balance will be:

2000000000000000000 Wei

Note: 1 Ether = 10^18 Wei. Solidity stores the balance in Wei.

### STEP 7: WITHDRAW MONEY

1. Find the withdraw function.
2. Enter 1000000000000000000 as the amount.
3. Click withdraw.
4. Wait for the transaction to complete.
5. Click showBalance again.

WHY?

The withdraw function checks the available balance, subtracts the requested amount and transfers Ether to the caller.

EXPECTED RESULT:
If 2 Ether was deposited and 1 Ether was withdrawn, the remaining balance will be:

1000000000000000000 Wei

### STEP 8: VERIFY THE RESULT

1. Click showBalance again.
2. Check the updated balance.
3. Observe the transaction status in Remix.

### IMPORTANT CONCEPTS:

1. Solidity: Programming language used to write smart contracts.
2. Smart Contract: Program stored and executed on a blockchain.
3. Remix IDE: Online tool for writing, compiling and deploying Solidity code.
4. Compiler: Converts Solidity code into executable bytecode.
5. Deploy: Publishes the contract to the selected blockchain environment.
6. Payable: Allows a function to receive Ether.
7. msg.value: Amount of Ether sent with a transaction, represented in Wei.
8. msg.sender: Address of the account calling the function.
9. require(): Checks a condition and stops execution if it is false.

## PRACTICAL 4: WRITE A SOLIDITY PROGRAM TO CREATE STUDENT DATA USING STRUCTURES, ARRAYS AND FALLBACK. DEPLOY IT ON ETHEREUM AND OBSERVE TRANSACTION FEE AND GAS VALUES.

### AIM:

### CONCEPT:

Array is used to store multiple records of the same structure.

Fallback is a special function that executes when a call does not match any other function. It can be payable to receive Ether.

Gas is the computational work required to execute a transaction.

Gas Used is the actual amount of gas consumed by a transaction.

Transaction Fee is the amount paid for processing a transaction.

### STEP 1: OPEN REMIX IDE

1. Open Google Chrome.
2. Visit https://remix.ethereum.org/
3. Open the File Explorer.
4. Open the contracts folder.
5. Click New File.

Remix IDE is used to write, compile and deploy Solidity smart contracts.

### STEP 2: WRITE THE SOLIDITY CODE

Copy and paste the complete code into StudentData.sol.

```solidity
// SPDX-License-Identifier: MIT
// Specifies the license of the smart contract.

pragma solidity ^0.8.0;
// Specifies the Solidity compiler version.

contract StudentData {
    // Creates a smart contract named StudentData.

    struct Student {
        // Structure groups the details of one student.
        uint id;
        string name;
        uint marks;
    }

    Student[] public students;
    // Creates an array to store multiple student records.
    // Public allows Remix to provide automatic access to stored records.

    function addStudent(uint _id, string memory _name, uint _marks) public {
        // Function accepts the student's ID, name and marks.
        // memory temporarily stores the string while the function executes.

        students.push(Student(_id, _name, _marks));
        // Adds a new student record to the students array.
    }

    function getStudent(uint index) public view returns (uint, string memory, uint) {
        // Reads student details using the array index.
        // view means this function reads data without changing blockchain storage.

        Student memory s = students[index];
        // Gets the student record at the given index and stores it temporarily.

        return (s.id, s.name, s.marks);
        // Returns the student's ID, name and marks.
    }

    fallback() external payable {
        // Executes when a call does not match another function.
        // payable allows this function to receive Ether.
    }
}
```

### STEP 3: COMPILE THE SMART CONTRACT

1. Click the Solidity Compiler icon on the left side.
2. Select compiler version 0.8.x.
3. Make sure it matches the pragma statement.

## PRACTICAL 5: WRITE A SURVEY REPORT ON TYPES OF BLOCKCHAINS AND THEIR REAL-TIME USE CASES

### AIM:
To study different types of blockchains and their real-time applications.

### INTRODUCTION:

Blockchain is a distributed digital ledger used to store information and transactions securely.

Data is stored in blocks that are connected to each other. Once recorded, data is difficult to modify.

Blockchain provides transparency, security and decentralization.

### TYPES OF BLOCKCHAINS:

There are four main types of blockchains:

### 1. PUBLIC BLOCKCHAIN

- A public blockchain is open to everyone.
- Anyone can join the network, view transactions and participate according to network rules.
- It is decentralized and transparent.
- Examples: Bitcoin and Ethereum.

REAL-TIME USE CASES:
1. Cryptocurrency transactions.
2. Decentralized applications.
3. Digital payments.
4. Smart contracts.

### 2. PRIVATE BLOCKCHAIN

- A private blockchain is controlled by a single organization.
- Only authorized users can access the network.
- It provides controlled access and privacy.
- Example: A company's private blockchain network.

REAL-TIME USE CASES:
1. Company record management.
2. Internal financial transactions.
3. Supply chain management.
4. Secure business data sharing.

### 3. CONSORTIUM BLOCKCHAIN

- A consortium blockchain is managed by multiple selected organizations.
- Only authorized organizations can participate.
- It allows organizations to share information securely.
- Example: A blockchain network shared by multiple banks.

REAL-TIME USE CASES:
1. Banking and financial services.
2. Supply chain tracking.
3. Healthcare data sharing.
4. Inter-organizational business transactions.

### 4. HYBRID BLOCKCHAIN

- A hybrid blockchain combines features of public and private blockchains.
- Some information is private, while selected information can be made publicly accessible.
- It provides both privacy and transparency.

REAL-TIME USE CASES:
1. Healthcare record management.
2. Government services.
3. Real estate management.
4. Business and supply chain management.

### COMPARISON OF BLOCKCHAIN TYPES:

1. Public Blockchain:
   - Access: Open to everyone.
   - Control: Decentralized.
   - Example: Bitcoin and Ethereum.

2. Private Blockchain:
   - Access: Authorized users only.
   - Control: Single organization.
   - Example: Company record management.

3. Consortium Blockchain:
   - Access: Selected organizations.
   - Control: Multiple organizations.
   - Example: Banking networks.

4. Hybrid Blockchain:
   - Access: Combination of public and private access.
   - Control: Depends on the network design.
   - Example: Healthcare and government systems.

### REAL-TIME APPLICATIONS OF BLOCKCHAIN:

1. BANKING:
   Blockchain helps record financial transactions securely and transparently.

2. HEALTHCARE:
   It helps maintain and share medical records securely between authorized users.

3. SUPPLY CHAIN:
   It helps track products from manufacturers to customers.

4. VOTING:
   Blockchain can be used to maintain transparent and tamper-resistant voting records.

5. EDUCATION:
   It can store and verify educational certificates and academic records.

6. REAL ESTATE:
   It can maintain property ownership and transaction records.

7. CRYPTOCURRENCY:
   It supports digital currencies such as Bitcoin and Ether.

### ADVANTAGES OF BLOCKCHAIN:

1. Transparency: Transactions can be verified by permitted network participants.
2. Security: Cryptographic techniques help protect stored data.
3. Decentralization: Public blockchain networks do not depend on one central authority.
4. Traceability: Transactions can be tracked.
5. Data Integrity: Recorded information is difficult to modify without detection.

### LIMITATIONS OF BLOCKCHAIN:

1. Some blockchain networks have high transaction fees.
2. Certain networks have slower transaction processing.
3. Implementation can be complex.
4. Some blockchain systems consume significant energy.
5. Privacy and regulatory requirements can create challenges.

### RESULT:
Successfully studied the four main types of blockchains: Public, Private, Consortium and Hybrid, along with their features, advantages, limitations and real-time applications.

Q3. What is Public Blockchain?
Ans: A blockchain that is open to everyone.

Q4. Give examples of Public Blockchain.
Ans: Bitcoin and Ethereum.

Q5. What is Private Blockchain?
Ans: A blockchain controlled by a single organization with restricted access.

Q6. What is Consortium Blockchain?
Ans: A blockchain managed by multiple selected organizations.

Q7. What is Hybrid Blockchain?
Ans: A blockchain that combines public and private blockchain features.

Q8. What is the difference between Public and Private Blockchain?
Ans: Public blockchain is open to everyone, while private blockchain allows only authorized users.

Q9. What are the applications of Blockchain?
Ans: Banking, healthcare, supply chain, voting, education and real estate.

Q10. What is the main advantage of Blockchain?
Ans: It provides security, transparency and data integrity.

Q11. What is Decentralization?
Ans: Decentralization means control is distributed among network participants instead of one central authority.

Q12. What is a Smart Contract?
Ans: A smart contract is a program stored on a blockchain that executes automatically when conditions are met.

Q13. What is Bitcoin?
Ans: Bitcoin is a digital cryptocurrency that operates on a public blockchain.

Q14. What is Ethereum?
Ans: Ethereum is a blockchain platform that supports smart contracts and decentralized applications.

Q15. Can blockchain data be changed?
Ans: Recorded blockchain data is difficult to modify without detection.
